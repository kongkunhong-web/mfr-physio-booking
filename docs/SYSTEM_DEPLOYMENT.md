# 系統部署說明

## 1. 文件目的

本文件說明網站由示範環境轉為正式部署時需要處理的系統、資料庫及安全項目。GitHub 倉庫內容包括原始碼、SQL migrations、設定檔和示範資料。

## 2. 現行系統邊界

目前前端、API 和資料庫操作已具備完整示範流程，包括：

- 患者資料錄入、優先級、預計通知日期及帳號開通；
- ELE、GYM、OT 類別及子類；
- A 班、B 班及星期一特別療程；
- 固定治療師、固定時間、容量及不可預約時段檢查；
- 患者預約、療程摘要及電話求助；
- 後台月曆、時間表矩陣、Excel 輸出、改期及轉治療師；
- 治療師病假／會議引致的批量轉移預覽；
- 醫生、治療師、假期、容量和示範資料管理。

## 3. 正式部署需要處理的部分

### 身份及權限

目前後台使用硬編碼密碼 `admin` 和固定 session `demo-admin`，只適合示範。正式版本應改用安全的身份認證，並至少區分系統管理員、排期人員、治療師及只讀查詢角色。

### 資料庫

現行 Cloudflare D1 採 SQLite 相容語法。若改用 SQL Server、Oracle Database、PostgreSQL 或其他平台，需重新評估資料型別、日期函數、交易、唯一索引、外鍵及併發控制。

### 醫療系統介接

正式 HIS 介接涵蓋患者主索引、轉介資料、身份核對、預約結果回寫及取消／改期同步，確保各系統資料一致。

### SMS 及通知

正式 SMS 功能包括短訊服務連接、重試、失敗處理、發送狀態回報和訊息範本審批。

### 時間與假期

現行服務時間以 UTC+8 計算。正式版本應統一伺服器時區、公眾假期來源、臨時停診及人手覆寫規則。

## 4. 正式使用前最低要求

1. 使用獨立的正式帳號、聯絡資料、登入設定及初始資料。
2. 建立正式身份驗證、角色權限、session 到期及帳號停用機制。
3. 加入操作審計，記錄新增、修改、刪除、開通、改期及批量轉移的操作者與時間。
4. 對患者身份證及電話採最少權限、傳輸加密、儲存保護及畫面遮罩。
5. 建立資料備份、復原演練、保留期限及刪除政策。
6. 以資料庫 transaction 或等效機制處理多人同時搶位及批量轉移。
7. 完成資訊安全測試、私隱影響評估、壓力測試及使用者驗收測試。
8. 設定正式監察、錯誤告警、服務健康檢查及事故處理流程。

## 5. 建議移植次序

1. 在隔離測試環境建立資料庫並依序執行 migrations。
2. 以假資料驗證所有 API 和排期規則。
3. 接入正式身份認證及角色權限系統。
4. 建立 HIS 及 SMS 測試介面。
5. 執行權限、併發、備份復原及資安測試。
6. 由復康科完成業務規則和畫面驗收。
7. 小規模試行並收集數據，再決定正式上線範圍。
